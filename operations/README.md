# Estate Operations Board

Status: Active
Owner: Alfred / Chief of Staff
Classification: Estate Internal
Introduced By: EC-000086
Date: 2026-06-30

## Purpose

The Estate Operations Board is the lightweight operational workspace for current Estate execution.

It is not a project management system.
It is not a replacement for GitHub Issues.
It is not a backlog.

It exists so the Steward can answer, in less than one minute:

- What is the Estate doing today?
- What is waiting?
- What is blocked?
- What ideas have been intentionally deferred?
- What should happen next?

## Board Surfaces

| Surface | Purpose |
|---|---|
| Daily Task Board | Today's operational commitments |
| Active Work Board | Multi-day and strategic efforts |
| Parking Lot | Deferred institutional thinking |
| Strategic Roadmap | Long-horizon Estate capability map |
| Review Cadence | Operational rhythm for review and planning |

## Operating Principles

Prefer strengthening existing institutions over creating new ones.

Architect once. Automate many times.

Automate stable patterns, not experimental ones.

The Estate invests effort where the return compounds over time.

Reduce the Steward's cognitive burden wherever practical.

Keep the board readable in seconds.

## Relationship to Collaboration Layer

The Collaboration Layer carries messages, work packages, claims, review state, and promotion records.

The Operations Board summarizes accepted operational truth.

The Collaboration Layer is the communication system.
The Operations Board is the operational visibility surface.

## Relationship to GitHub

GitHub may store approved Estate Internal operational board files.

GitHub Issues are not duplicated here.

The Operations Board tracks institutional operating state, not every implementation task.

## Relationship to Alfred

Alfred is the future operational coordinator for this board.

In v1, humans and workers update these markdown surfaces manually.

Automation should wait until update patterns stabilize.
