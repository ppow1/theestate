# WP-4112 Measurement Variant Review Workflow

## Authority and boundaries

This workflow extends the WP-4108 Visual Bible repository, WP-4109 versioned physical specification, and **references** WP-4111 `scale_profile_id` and `camera_profile_id`. It does not define parallel camera, height, footwear-presentation, or scale records. A measurement variant is a temporary candidate—not an identity, public portrayal, or canonical record.

No imagery is generated by this implementation. Detailed comparison data is restricted by default. Evelyn's values in the source canon remain provisional calibration context: they are not copied into a fixture, accepted as canon, or used as a default range.

## Operator procedure

1. Create one bounded question and a resident-owned range policy. Record exact values and units for A (lower/narrower), B (center/baseline), and C (higher/fuller). Custom dimensions require explicit authorization.
2. Declare tested fields. Lock identity, facial fingerprint, adult age presentation, hair, expression, pose, the existing WP-4111 camera and scale references, lighting, background, wardrobe, footwear, heel height, dimensions, model/version, deterministic seed/equivalent, prompts, and settings.
3. Use one opaque, adult-appropriate, non-explicit neutral/fitted/silhouette-revealing outfit with identical cut and material. It must reveal—not manufacture—the tested difference.
4. Produce the five ordered views for every candidate. Assemble the primary `vertical_A_B_C` sheet so B is centered. Keep canvas, floor line, top margin, and anatomical guides aligned; never resize a variant independently. A same-angle matrix is supplemental only.
5. If heels are compatible, complete a cycle at 3 inches or greater and record heel-adjusted presentation and posture separately from standing height and body measurements. Otherwise record the role, mobility, safety, wardrobe, or canon exemption.
6. Preserve the manifest, exact prompts, negative prompts, seed, model/workflow hashes, asset references, revision history, supersession links, and lineage. Never substitute unlabeled visual differences.
7. Run schema validation and `validate_comparison_set`. Only a complete set with evidenced normal-size legibility may enter Steward review.

## Legibility, regeneration, and escalation

`pass` requires an evidence reference at the declared normal review size. `fail` or `ambiguous` blocks review and requires diagnostic codes plus a bounded regeneration request. Corrections may adjust spread **inside existing resident bounds**, improve fitted wardrobe/alignment/camera/footwear/annotation/resolution/prompts, restore identity locks, or escalate to the Steward. The validator never silently accepts, selects, or widens a range.

Escalate metadata defects at level 0; layout/wardrobe at level 1; pose/camera/identity/control failures at level 2; missing or altered decision evidence at level 3; and unauthorized canonical mutation at level 4.

## Steward review surface

Review the vertical sheet directly at its declared normal size, then inspect the supplemental angle matrix. Confirm identity and controls before judging the tested measurements. Outcomes are select A/B/C, reject all, narrow/widen within separately approved bounds, isolate variables, or defer. Record rationale, confidence, concerns, reviewer identity, timestamp, rejected evidence references, and superseded decision IDs.

Selection is `selected_but_unapproved`. Only an explicit Steward decision can become `steward_approved`; a separate promotion record then creates a new WP-4109 physical-specification version while preserving its predecessor, every candidate, the sheet, rationale, and audit lineage. Automation and non-Steward reviewers cannot promote.

## Machine-readable surfaces

- `measurement_comparison_set_v1.schema.json`: A/B/C, exact measurements, controls, range policy, artifacts, lifecycle, provenance, privacy.
- `measurement_review_records_v1.schema.json`: provenance, append-only decisions, regeneration, and promotion records.
- `measurement_review.py`: semantic completeness, equality, authorization, range, layout, heel, legibility, decision, and promotion gates.
- `wp4112_three_variant_generation_template.json`: neutral generation/assembly contract; it contains no resident values.
