# Visual Bible Foundation Guide

The Visual Bible foundation defines governed, reproducible visual identity records for adult Estate residents. It separates written specifications from generated assets, and separates canonical imagery from candidates, rejected outputs, superseded material, comparison sheets, thumbnails, group images, and restricted/private layers.

## Directory Standard

Each resident lives under `data/visual_bibles/residents/<resident>/` with `public`, `internal`, `restricted`, and `private` layers. Each layer has specifications, prompts, negative prompts, reviews, Steward Notes, locks, and asset buckets for canonical, candidates, rejected, superseded, comparisons, turnarounds, thumbnails, and group images.

Restricted and private layers are auditable and loadable only by explicit scope. They are not default identity material and must not be used to bypass HR, Security, or governance review.

## Canonical Rules

Generated or imported images begin as candidates unless an explicit Steward approval record promotes them. Canonical locks require accepted physical, facial, wardrobe, prompt, negative-prompt, and asset manifest hashes. Rejected and candidate assets cannot share canonical state or canonical directories.

## Measurement Variant Reviews

Controlled comparisons use exactly three variants when calibration is required. The same resident identity, facial fingerprint, pose, expression, camera position, focal length, lighting, background, and wardrobe must be fixed. Rows must be vertically aligned across front, front three-quarter, side, rear three-quarter, and rear views. At least one applicable comparison set must use heels of 3 inches or more.
