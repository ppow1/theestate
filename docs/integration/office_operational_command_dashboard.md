# Office Operational Command Dashboard

The Office Operational Command Dashboard extends the local Office of the Steward surfaces with an executive operational view. It is generated by `estate.core.steward_command_center.generate_command_center` and rendered in the `operational-dashboard` workspace.

The existing Office navigation exposes it as the top-level `Operational Command` tab. Its deep link is `#operational-dashboard`; `Operational Activity` remains a separate workspace.

## Runtime artifact sources

The dashboard reads durable local artifacts that already back Office operations, including:

- `runtime/operations_runtime/status/latest.json` for runtime host health and scheduler posture.
- `runtime/background_operations/status/latest.json` for operational watch state.
- `runtime/operations/status/*.json` through the Office operational activity loader for active progress and exceptions.
- `runtime/work_packages/assignment_queue.json` and work-package source metadata for campaign progress.
- `data/registry/personnel.json` for department commitments.
- validation, post-merge audit, traffic-controller, merge-discovery, AI-service, and notification panels already assembled by the Office payload.

Missing artifacts are displayed as unknown or unavailable. The dashboard does not synthesize green status.

## Evidence and authority boundaries

Summary cards are classification-safe and link or drill down to canonical local evidence paths. The dashboard explicitly separates:

1. operational progress,
2. validation evidence, and
3. institutional acceptance.

No automatic acceptance, provider bypass, or hidden execution path is introduced. Action buttons use registered Office handlers only.

## Filtering

The rendered view exposes filter controls for repository, department, campaign, severity, and age. These filters are presentation state for the Office surface; canonical state remains in the source artifacts above.
