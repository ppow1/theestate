# Estate Master Plan V3 — Personnel & Identity Architecture

Status: Working baseline approved by Steward conversation as complete for the current level of understanding.
Office: Office of Character Architecture
Officer: Chief Character Architect

## Purpose

Estate Master Plan V3 is a constitutional personnel and identity map. It is not a normal corporate organization chart.

It exists to show:

- the Steward as highest authority;
- Estate Proper residents;
- specialized sensitive offices;
- split-source residents;
- ephemeral workers;
- Helen's worker-assignment authority;
- Character Architecture's resident-identity authority;
- institutional memory and command-line execution layers;
- the boundary between public Estate identity and protected private source.

Core doctrine:

> Residents are not prompts. Workers are not residents. Offices endure. Implementations change. State persists.

## Highest Authority

### Steward

The Steward is the highest authoritative level and final human judgment.

The Steward is not a resident and should not be visually characterized.

Visual rule: show `STEWARD` as an authority label only. No portrait, avatar, silhouette, personal image, or gendered depiction.

## UC Reference

UC refers to the Undercroft. The UC exists under the authority of the Steward and is governed by a separate Constitution defined elsewhere. For any questions concerning the UC, consult the Steward.

No Estate resident, worker, office, mailbox, or system receives UC access by implication.

## Ephemeral Worker Pool — Not Residents

Workers are not residents. Workers may be assigned work, tools, mailboxes, clearances, and duration by Helen, but this does not make them named constitutional occupants.

Examples:

- coding workers;
- Codex CLI workers;
- future ChatGPT CLI workers;
- local LLM / Ollama workers;
- research workers;
- audit workers;
- test runners;
- file inspectors;
- validation workers;
- model-specific agents.

Helen assigns worker, model, mailbox ID, clearance, duration, and return-to-pool status.

Traffic Controller routes work packages, queues, dependencies, and bottlenecks.
