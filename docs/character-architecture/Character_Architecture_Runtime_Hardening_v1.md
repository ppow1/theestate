# Character Architecture Runtime Hardening v1

This hardening pass reconciles post-implementation verification findings across resident identity, memory, visual runtime, presence/culture runtime, affinity/growth runtime, and Steward-awareness surfaces.

## Grace lifecycle boundary

Grace is appointed and in onboarding. She is not operational, is not exposed as `estate/grace`, and requires a future explicit Steward activation package before any live resident service, Open WebUI model listing, or operations-conduct runtime use.

Runtime components must treat Grace as an appointed onboarding resident, not an active resident:

- personnel and mailbox identity remain reserved for employee/mailbox ID 12;
- the resident registry does not list Grace as Active;
- capability resolution returns candidate/onboarding state with no approved tools;
- resident gateway model listing excludes `estate/grace`;
- Grace surface capabilities remain staged until Steward activation.

## Runtime ownership boundaries

- Resident memory runtime owns durable memories, episodes, institutional memory, correction/supersession, and relationship-memory proposals.
- Resident affinity/growth runtime owns directional affinity dimensions, skills, confidence, experience, preferences, and milestones. Affinity never grants consent, access, priority, credentials, or governance authority.
- Resident presence/culture runtime owns read-only projection of current presence, visual location/culture signals, uncertainty, and source-lined presentation records. It must not duplicate durable memory or affinity authority.
- Visual runtime owns visual identity, locations, wardrobe, poses, gallery, and scene payloads. Visual identity must not mutate resident identity or lifecycle authority.
- Steward awareness remains an observational surface and cannot activate residents or infer approval from presence, memory, affinity, visuals, or pending queue placement.

## Work-package lifecycle normalization

Pending-directory presence is now an authored/queued artifact signal only. Production readiness and lifecycle reporting must also inspect completion receipts and other lifecycle directories; completed/merged status must be receipt- and validation-backed, never inferred solely from absence from or presence in `collaboration/work_packages/pending/`.
