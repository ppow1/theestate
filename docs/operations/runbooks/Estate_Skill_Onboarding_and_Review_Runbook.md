# Estate Skill Onboarding and Review Runbook

1. Author the closed manifest from the template. Declare owner, maintainer, capabilities, providers/tools, authority, bounded reads/writes, stop conditions, and evidence contracts.
2. Run schema and semantic validation. Reject placeholders, absolute/traversing references, hidden authority, unbounded wildcards, undeclared writes, missing timeout/stop/partial behavior, and alias collisions.
3. Review with Engineering/owner authorization, Helen readiness, Operations, Dispatch, provider/tool owner, and resident owner as applicable. Record gaps; do not infer authority from registration or provider health.
4. Register at maturity 1. Promote only through evidence: dependencies available, governance approved, readiness checks passed, and bounded acceptance. Institutional acceptance remains a separate Steward decision.
5. Ask Grace “What Skills can check Git?” or use a formal name/alias. Discovery and help never execute. Request proposal-only or explicitly say to execute now; exact request provenance is retained.
6. Before execution inspect authority, scope, freshness, stop/cancel behavior, and terminal states. Stop/cancel leaves truthful blocked or partial evidence. Replays use invocation identity; conflicting artifacts stop and escalate.
7. Review receipt, artifact, validation, reconciliation, and terminal result. A completed Skill is not institutional acceptance.
8. To propose a Skill, submit its manifest, owner, worked example, threat/scope analysis, tests, readiness checklist, rollback, and acceptance plan.
