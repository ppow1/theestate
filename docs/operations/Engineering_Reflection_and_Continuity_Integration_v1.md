# Engineering Reflection and Continuity Integration v1

Status: Gate C operational contract  
Governing authority: `docs/operations/ChatGPT_Worker_Reflection_and_Continuity_Process_v1.md`

## Boundary

This document maps Engineering events into the existing reflection process; it does not replace or amend it. `AI_REFLECTION_HINTS.md`, the master process, its template, completed examples, and pilot remain the required reading order. Renewal preserves an officeholder and changes its implementation; it does not create an employee or transfer institutional authority.

## Trigger and artifact matrix

| Condition | Required response/artifact | Coordination and stop rule |
|---|---|---|
| context congestion, repeated state loss, severe latency/drift | full Reflection Package + Execution Handoff Addendum | Grace supplies evidence; Helen owns renewal readiness; current worker safe-stops |
| planned Chief Architect reflection point or long-running campaign rollover | full package/addendum; bounded onboarding manifest/hashes | Steward may define restart assignment; Helen verifies onboarding |
| worker replacement without identity renewal | bounded execution handoff; full package if officeholder implementation is renewed or continuity cannot be bounded | assignment/branch owner explicitly transfers; replacement reads canonical sources |
| provider failure mid-package | attempt reconciliation + bounded execution handoff to new attempt | preserve partial evidence; fresh routing/selection/Dispatch; no silent fallback |
| branch or PR ownership transfer | Execution Handoff Addendum (or bounded handoff for simple, verified transfer) plus explicit branch reassignment record | old owner remains until acknowledgement and canonical transfer event |
| interrupted validation | bounded validation handoff naming recipe, commit, environment, completed/remaining steps and partial reports | validator must not infer pass; resume or rerun per recipe |
| unresolved authority blocker | bounded handoff + canonical decision request; full reflection only if worker-health trigger also exists | fail closed; do not invent waiver |
| provider/worker pilot or renewed implementation qualification | renewal/pilot record in the existing continuity surface | include scope, qualification evidence, lessons and expiry |

A **simple bounded handoff** is allowed only when identity remains stable, sources are complete, scope is small, no context-health trigger exists, and receiver can verify branch/state/evidence. It includes IDs, assignment, branch/base/head/owner, canonical state refs, exact last verified action, next authorized action, commands/results, blockers, evidence links, prohibited actions, and acknowledgement. Otherwise use the master template and full artifacts.

## Mandatory continuity controls

Before transfer, reconcile PTM state, definition digest, branch/PR head, Dispatch/provider attempt, validation commit, blockers, messages, Notebook index, receipt and acceptance state. Label inherited claims versus current verification. Preserve predecessor implementation as read-only fallback until the renewed implementation completes its first bounded assignment, as the master process requires.

The restart command must name the campaign/package, required reading ledger, exact repository/branch and source high-watermark, first bounded action, validation boundary, and forbidden actions (merge, self-acceptance, gate release, priority/authority changes). Artifacts link canonical evidence rather than copying mutable status or raw transcripts.

## Completeness gate

Continuity is `verified` only when every required file exists and is complete/readable; manifest/hashes verify where required; assignment and branch ownership agree; exact next action and uncertainties are explicit; acknowledgement is durable; and a fresh worker can resume without chat history. Missing or contradictory evidence yields `continuity_blocked`, is visible in the operational view, and prevents ownership-dependent execution.
