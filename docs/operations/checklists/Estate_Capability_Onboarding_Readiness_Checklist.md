# Estate Capability Onboarding Readiness Checklist

Every unchecked item is a blocker or needs an explicit not_applicable rationale.

## Identity and ownership

- [ ] No duplicate capability/provider/adapter; existing registries searched.
- [ ] Stable capability ID/version, resident/department owner, taxonomy, and worker recorded.
- [ ] Target maturity and transition authority recorded.
- [ ] Provider, adapter/tool, implementation kind, runtime/service/model exact.

## Authority and evidence

- [ ] Authority, prohibited actions, classification, network, credentials, and worker limits explicit.
- [ ] Exact inputs, reads, writes, outputs, or N/A rationales present.
- [ ] Prompt/source/request provenance, type, digest, originator, freshness present.
- [ ] Health, capacity, qualification, authorization, and freshness evidence separate and current.
- [ ] PTM/readiness and Dispatch/handoff dependencies included where applicable.
- [ ] Closed schemas, canonical records, create-once persistence, digest, replay, and conflict behavior defined.

## Runtime and validation

- [ ] Existing catalog/capability source reused; no duplicate registry or lifecycle.
- [ ] Resident manifest, service/adapter registration, discovery, and limitations synchronized.
- [ ] Installed runtime/service/model and endpoint policy verified.
- [ ] Unit, schema, integration, negative, replay/collision/cancellation tests pass.
- [ ] Live governed acceptance complete for Level 4, or lower-level/non-execution exemption recorded.
- [ ] Artifact/receipt hashes, reconciliation, operator docs, availability, and limitations published.
- [ ] Rollback, deprecation, queue drain, partial output, and historical evidence preservation defined.
- [ ] Institutional acceptance remains separate.
- [ ] Worker did not exceed package authority.

## Stop gate

- [ ] No unresolved owner, classification, scope, credential, network, schema, worker, bootstrap, or reserved-authority question.
- [ ] Steward-stop conditions and exact next decision recorded.
