WP-4112 requires a repeatable process for comparing nearby physical-measurement alternatives before a resident’s canonical proportions are locked. It addresses the fact that small changes in bust or chest, waist, hips, shoulders, torso, legs, and overall build are hard to judge when imagery differs in pose, scale, clothing, camera, lighting, or footwear.

The package establishes a three-variant standard—A as the lower or narrower candidate, B as the center or preferred candidate, and C as the higher or fuller candidate—and requires that only approved tested dimensions change while all other identity traits remain locked.

# 1. Canonical Purpose

The Measurement Variant Review Workflow exists to convert subtle physical-design questions into controlled, auditable comparison decisions.

Its purpose is not to create alternate versions of a resident.

Its purpose is to let the Steward answer bounded questions such as:

- 

Should the canonical waist be slightly narrower or fuller?

- 

Does a modest shoulder-width change better fit the resident’s role?

- 

Is the likely center bust or chest measurement visually correct?

- 

Does one torso-length option preserve the resident’s identity better?

- 

Is the leg-to-torso balance consistent with the approved height?

- 

Does the center build remain recognizably distinct from neighboring variants?

- 

Is the difference too subtle to support a responsible decision?

A valid workflow must preserve identity while exposing only the intended physical variation.

# 2. Governing Principles

## 2.1 Variants are candidates, not identities

Variant A, Variant B, and Variant C are temporary review constructs.

They do not represent:

- 

separate residents;

- 

alternate personalities;

- 

alternate biographies;

- 

alternate facial identities;

- 

approved public portrayals;

- 

canonical body specifications unless selected and approved.

This distinction is explicit in the work package.

## 2.2 Only declared variables may change

Every comparison set must declare the tested dimensions before generation.

Examples:

```

```
TESTED:
- waist circumference
- hip circumference

LOCKED:
- face
- age presentation
- height
- shoulder width
- torso length
- leg length
- hairstyle
- expression
- posture
- footwear
- camera
- wardrobe
```

```

Any undeclared material change invalidates the comparison.

## 2.3 Variant B is the practical center

Where practical:

- 

A is lower, narrower, shorter, or lighter in the tested dimension;

- 

B is the baseline, center, or likely preferred candidate;

- 

C is higher, fuller, longer, or broader.

Variant labels do not imply quality ranking.

B is not automatically canonical.

## 2.4 Resident-specific spacing

Variant spacing must reflect the resident’s established design.

A tightly constrained resident may use narrow differences.

A less established resident may require broader exploratory ranges.

No universal increment may be imposed across all residents.

## 2.5 Visual judgment requires controlled conditions

A comparison is invalid if the variants differ materially in:

- 

pose;

- 

head angle;

- 

expression;

- 

camera;

- 

focal length;

- 

crop;

- 

lighting;

- 

hairstyle;

- 

wardrobe;

- 

garment stretch;

- 

footwear;

- 

heel height;

- 

image scale;

- 

rendering model;

- 

major generation settings.

## 2.6 Legibility precedes decision

The Steward must never be asked to select among differences that cannot reasonably be seen.

If the intended change is not legible at normal review size, the correct outcome is:

```

```
COMPARISON FAILED — REGENERATION REQUIRED
```

```

not:

```

```
NO PREFERENCE — ACCEPT BASELINE
```

```

## 2.7 Rejected variants remain evidence

A rejected variant must not be erased.

It remains part of:

- 

the decision history;

- 

negative guidance;

- 

future revision context;

- 

provenance;

- 

audit;

- 

comparison calibration.

## 2.8 Selection does not itself alter canon

A selected candidate becomes eligible for canonical promotion.

It does not become canonical until the Steward explicitly approves the corresponding physical-specification update.

# 3. Scope

## 3.1 Supported tested dimensions

The workflow must support:

- 

bust circumference;

- 

chest circumference;

- 

waist circumference;

- 

hip circumference;

- 

shoulder width;

- 

torso length;

- 

leg length;

- 

inseam;

- 

waist placement;

- 

overall build;

- 

silhouette balance;

- 

another explicitly approved physical parameter.

The source package expressly permits these categories.

## 3.2 Multi-variable comparison

A set may test more than one dimension only when:

- 

the dimensions are meaningfully related;

- 

the combination is explicitly declared;

- 

the individual values remain exact;

- 

the resulting interpretation remains understandable.

Example:

```

```
A: 32B–21–30
B: 33B–21–31
C: 34B–22–32
```

```

This tests a coordinated silhouette family.

It is not suitable for determining independently which single measurement caused the preferred result.

## 3.3 Single-variable comparison

When causality matters, one dimension should vary at a time.

Example:

```

```
A: waist 20.5 in
B: waist 21.0 in
C: waist 21.5 in
```

```

All other values remain locked.

## 3.4 Out of scope

This workflow does not:

- 

decide every resident’s measurements;

- 

generate the final canonical image library;

- 

authorize explicit imagery;

- 

change unrelated identity trait
