# 19. Environmental Scale References

## 19.1 Standard objects

Approved references may include:

- 

doorway;

- 

chair;

- 

desk;

- 

countertop;

- 

stair tread and riser;

- 

couch;

- 

railing;

- 

standardized wall markers.

## 19.2 Environmental object schema

```
YAML
```
environmental_scale_object:
  object_id: scale-object-uuid
  object_type: doorway
  dimensions:
    height_cm: 203.2
    width_cm: 91.44
  tolerance_cm: 0.5
  source_reference: standard-id
  perspective_sensitive: true
  approved_assets: []

## 19.3 Environment use rules

Environmental scale is valid only when:

- 

object dimensions are known;

- 

subject and object occupy compatible depth planes;

- 

perspective is controlled;

- 

the floor plane is coherent;

- 

no hidden platform or elevation exists;

- 

the object has not been resized independently.

# 20. Doorway Reference Standard

A doorway reference must record:

- 

doorway height;

- 

doorway width;

- 

resident distance from the doorway;

- 

camera distance;

- 

camera height;

- 

floor continuity;

- 

footwear;

- 

posture;

- 

crop;

- 

lens.

A resident standing several feet in front of a doorway cannot be compared directly without perspective correction.

# 21. Desk Reference Standard

A desk reference must record:

- 

desk height;

- 

desktop thickness;

- 

resident position;

- 

seated or standing condition;

- 

footwear;

- 

camera geometry;

- 

hand and elbow relation;

- 

whether the desk is standard or custom-sized.

Desk images validate:

- 

arm reach;

- 

torso length;

- 

shoulder position;

- 

seated or standing scale;

- 

furniture plausibility.

# 22. Chair Reference Standard

At least one standardized chair should be used across residents where practical.

This allows direct comparison of:

- 

seated torso height;

- 

knee position;

- 

foot contact;

- 

shoulder height;

- 

head height;

- 

body compactness.

A custom chair must be clearly marked and must not be used as a universal scale reference.

# 24. Group-Photo Relative-Height Validation

A group image passes only when:

- 

approved height ordering is preserved;

- 

residents share a coherent floor plane;

- 

camera perspective explains any apparent compression;

- 

footwear conditions are known;

- 

posture differences do not reverse ordering;

- 

no resident is independently resized;

- 

the relationship can be judged without captions.

WP-4111 explicitly prohibits canonical group imagery when scale is inferred only from captions or perspective makes ordering ambiguous.

## 24.1 Group ordering rules

The system should maintain:

```
YAML
```
resident_height_order:
  - resident-tallest
  - resident-middle
  - resident-shortest
```

```

Ties or near-equal heights should include tolerance bands.

## 24.2 Perspective exceptions

A shorter resident may appear taller in image coordinates when:

- 

closer to the camera;

- 

standing on a higher plane;

- 

wearing materially higher footwear;

- 

another resident is seated or leaning.

Such an image must record those conditions and may not serve as neutral relative-height proof.

# 26. Vertical Alignment Rules

When comparing variants:

- 

floor lines must align;

- 

canvas dimensions must match;

- 

image scale must match;

- 

top-of-head alignment must reflect actual height differences rather than forced normalization;

- 

equivalent anatomical landmarks should align where the tested variable allows;

- 

horizontal guides should be visible or machine-readable;

- 

labels must not cover the body;

- 

image padding must be standardized.

## 26.1 Landmark alignment caution

If the tested variable is leg length, waist and knee landmarks may intentionally differ.

The system must not artificially align all landmarks and thereby erase the variation being tested.
