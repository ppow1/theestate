# WP-4053 Integration Notes

## Resident context assembly
Install as a read-only preference resolver after registry identity loading. Context assembly should request scoped records by resident, domain, audience, and session context. Never merge private relationship-layer preferences into Office, HR, global search, or other resident payloads.

## Session continuity
Continuity summaries may submit compact `Evidence` references and preference-change proposals. Raw transcripts should remain in existing transcript/summary systems and should not be duplicated here.

## Evaluator and gateway
The evaluator should reject proposals that target identity anchors, authority, appointment status, protected history, or relationship boundaries unless Steward-approved. Gateways should pass only accepted evidence references, never raw model improvisation as durable continuity.

## Visual/avatar future systems
Voice/model/avatar presentation preferences can use normal domains but must remain separate from tool authority and identity anchors. Avatar-sensitive/private presentation records require the private privacy path.

## Install handoff
Future INSTALL-HANDOFF should map staged schemas into active schema registry, add a durable storage adapter, add resident-context filtering hooks, and wire proposal review to Steward-approved continuity workflows.
